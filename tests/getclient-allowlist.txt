# Format:  path | scope | normalized-content  # reason
#
# Each entry ANCHORS a sanctioned `getClient()` site by CONTENT, not by line
# number, so inserting or removing comment / JSDoc lines above a site never
# forces an edit here.
#
#   - path:               the src/ file, forward-slashed, relative to repo root.
#   - scope:              the name of the nearest enclosing named declaration
#                         (function / method / interface / class / const-binding).
#                         `(module)` if the site is at top level. A site that is
#                         itself a scope-opening declaration (e.g. the
#                         `export function getClient()` definition) has scope =
#                         its own name.
#   - normalized-content: the matched source line, trimmed with internal
#                         whitespace runs collapsed to single spaces.
#
# HOW MATCHING WORKS (test #22 in tests/outage-state.test.ts — the ONLY consumer):
# The audit enumerates src/**/*.ts, scans each line for `\bgetClient\(\)`
# (dropping lines that begin with whitespace + `*` or `//`, i.e. JSDoc-
# continuation and line comments — single-line `/** ... */` JSDoc is NOT
# dropped), resolves each hit's (scope, normalized-content), then performs an
# EXACT one-to-one assignment against the entries below. Counts are enforced:
# a duplicate identical call in the same scope needs its own entry.
#   - A hit with no matching entry  → "unsanctioned getClient()" violation,
#     named as `path:line (scope: X): content`.
#   - An entry that matched no hit  → "stale allowlist entry" failure.
# A comment/JSDoc insertion above a site leaves its anchor unchanged (no edit
# needed). A NEW site, or a site MOVED to a different function (its scope
# changes), fails and is named.
#

# genuinely sanctioned new site, copy the reported anchor (`path:line (scope:
# X): content`) into a `path | X | content  # reason` entry below. Do NOT add
