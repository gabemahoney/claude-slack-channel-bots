# Engineering Best Practices

## The two cardinal rules

**These two rules override everything else in this guide, every SRD, every plan and every review. No exception, no workaround, no "just this once".**

1. **CSCB relies on agent-director for agent state.**
2. **CSCB does not write code that parses an agent's TUI.**

What they mean:

- **Agent state is agent-director's answer, and only agent-director's.** "Working", "waiting", "at a prompt", "safe to type into", "stuck", "idle": CSCB gets each of these from agent-director's verbs and fields (row `state`, `family_state`, request records, and refusals such as `ErrDialogMaybeOpen`). CSCB acts on that answer and on agent-director's refusals. CSCB never works out agent state for itself.
- **No TUI parsing, of any kind.** CSCB never reads an agent's screen to decide anything: no footer, prompt marker, border, spinner, timer, menu, dialog, picker or status-line text, for Claude Code, Codex or any other agent. Pane text from `read-pane` is never matched, scanned or classified by CSCB code. Agents' TUIs are not a contract. They change every release, and code that reads them breaks every release.
- **If CSCB needs a state agent-director doesn't report, ask agent-director for it.** File a feature request in agent-director's repository and block the CSCB work on it. Never fill the gap by reading the screen.
- **Reviews enforce this.** Any SRD, plan, task or diff that reads an agent's TUI, or derives agent state in CSCB, is rejected, even if the SRD asks for it.

## Layering: agent-director Owns tmux

- **CSCB never touches tmux.** Every launch, pane read, keystroke, kill and liveness check goes through an injected agent-director client; another session owner would drift from agent-director's view.
- **CSCB never replicates agent-director functionality.** Use its verb and typed result, or file a feature request in its repository and block the dependent CSCB work.
- Keep one Claude session per persona, however many channels it serves. Fungible mode adds no session, launch, pane read, agent-director call or channel-membership lookup.
- Delivery uses `createDeliveryClientFactory` and `clientFor(key)`, with a separate client per persona. Preserve the common option builder, version/floor checks, outage wrapper, async-local persona client and budget hook across reconnect awaits, so one stalled client cannot stall siblings.
- Retained pane probes consume only agent-director success/error classes and discard the payload. Use `readPersonaOwnPane`; the CLI teardown and latch probe have their separate outcome-only paths. Never return pane text to policy, compute its hash or include it in diagnostics. A probe never proves idle or authorizes keys. The [call inventory](cardinal-delivery-verification.md) records the permitted probes.
- Build a human's exact attach target only through `tmuxExactSessionTarget` and `personaTmuxSessionName`, with `-t =<name>`. Test tmux behavior only in a throwaway container, never on the host's tmux server.
- Keep the agent-director client pin and runtime floor at released 0.12.0 or later; explicitly set `agent: "claude"` on spawns and templates. Use native error classes and required plural permission results with delivery fields. A recorded verdict is not confirmed delivery. Never use prior-session files as resume candidates or ordinary text to answer a fallen-back permission dialog. Keep HOME out of generated `extra_env`, validate environment keys, and use decimal integer arguments and unsigned durations.

See [The Server Reaches a Session Only Through agent-director](#the-server-reaches-a-session-only-through-agent-director) for the enforced boundary.

## The Server Reaches a Session Only Through agent-director

The server starts no tmux process and reaches a session only through agent-director, and never touches agent-director's `@ad_owner` label or its per-pane `@ad_pane` label. This preserves agent-director's ownership of every session. `tests/fmk-source-audit.test.ts` enforces the [Source Invariants](#source-invariants).

## Language, modules and code quality

Use strict TypeScript, Bun for runtime and tests, ES2022, ESNext modules with bundler resolution, and explicit `.ts` import extensions.

- Keep pure logic importable without effects; put mutable state inside factories or dedicated registries with reset seams. Keep HTTP/lifecycle wiring in `server.ts` and startup effects in `main()`: importing the server must create no Slack client, read no token and create no directory.
- Add persona start steps and event handling to the injected modules in the [module map](architecture.md#module-map), not to `server.ts`. Extract a concern with its own types/state/functions or when tests need an effect-free import; don't extract a few related functions prematurely.
- Keep `reload-preview-clauses.ts` and `startup-summary-ending.ts` free of every import, type-only imports included; re-export their texts unchanged from their owners. `ci-live/` imports no other `src/` module, so its host runner cannot load Slack, agent-director or `bun:sqlite` accidentally.
- A seam that forces a production path is underscore-prefixed, lives beside that path and runs its real code/classification. `_forceResumeForPersona` and `_forceReuseSpawnForPersona` are for the integration driver only; production never calls them. Unit cases compare calls, answers and effects with the equivalent production path, so the driver tests CSCB rather than an imitation.
- Remove dead code, unused imports/exports and debug output. Follow existing patterns, use named constants, share duplicated blocks and avoid hypothetical abstractions. Extract helpers beyond roughly 50 lines or three nesting levels so functions remain readable.
- Use camelCase for Maps and verb-first functions, PascalCase for interfaces, UPPER_SNAKE_CASE for constants, and descriptive `// ---` section comments.
- Spell a tool name once (`SET_CHANNEL_DELIVERY_TOOL` for `set_channel_delivery`), with exported text constants/builders and the injected `SessionToolDeps.log` (console fallback only when unset), so handlers, definitions and tests cannot drift.
- Key persona state by persona key, never channel, name or directory. Derive identifiers and environment through `persona-identity.ts`; render a named persona with `renderPersonaRef` or `formatPersonaDiagnostic`, and a key-only reference as `persona=<key>`, so all paths identify the same persona.

## Delivery ownership and adapters

Preserve the [intake](architecture.md#durable-intake-queue-bomv-sr-2sr-3), [engine](architecture.md#per-persona-delivery-engine-bomv-sr-5sr-6) and [reporting](architecture.md#delivery-reporting-and-reactions-bomv-sr-8) contracts.

- Keep `decideDelivery`, `decideEngine`, `decideGate` and head selection pure. Pass observations, durable facts and constants explicitly; inject clients, receipts, queues, clocks and timers. Engines/adapters start no I/O or timers on import, so decisions can be tested independently of execution.
- Intake order is fungible app-mention rule → durable Slack key check → decision → store → aggregate ack. Do no network work before the ack; failed storage suppresses it. Partial fanout retries prepare retained accepted-only targets without accepting them twice. Name lookups are bounded and concurrent; append immutable fixed parts before waking the engine. Failed preparation owns its retry timer; the engine must not steal pre-ack preparation.
- Post-ack recovery keeps its one gated row read and `decideLostMessageState` inputs. Only `firesHumanTriggeredRestart` (`starting-now`) schedules a human restart. Keep launch activity, sequence/wait activity and the shared work-in-flight gate distinct. Recovery posts nothing; intake probes no stream and sends no channel notice or ack reaction. Operational consumers use the connection fact alone.
- Delivery and reconnect text/Enter share the persona lifecycle lease across the text-to-Enter pause. Revalidate fresh agent-director `waiting` and non-screen guards before each key. Teardown/shutdown cancels delayed keys; startup dialogs receive no automatic answer. Preserve independent engine, gate and saved-key readings during an owned operation.
- Persist the attempt before keys and receipt-backed delivery before advancing the FIFO head/part. Classify text and Enter separately: definite text refusal differs from unknown outcome, and Enter failure does not erase typed text. Release the lease on append failure, retry the append and revalidate before further keys. Never cap production retypes, expire/discard accepted work or let another item pass blocked durable work.
- Keep exact own-message receipt schemas in `delivery-receipt.ts`. Transcripts confirm delivery only; they never establish idle/busy, native queue state, turn completion or compaction lifecycle. Preserve `tag_prompt` as a prerequisite. In `tag-wrapper.ts`, neutralize openers, then decimal-escape U+2028, U+0301 and U+0308 before splitting; retain all 15 wrapper cases and the exact receipt matcher.
- Emit delivery, retype, AD waiting/refusal, queue-age and missing-marker facts through `deliveryEngineEvents.emit`. A deferred reconnect belongs to the active engine or lifecycle timer; teardown/shutdown cancels that ownership.
- Reporting consumes real queue/engine streams and current `DeliveryStatus`; it never authorizes typing or infers delivery from send success. Only final durable `item-delivered` drives the delivered log/reaction. Keep actual first-dispatch excerpts separate from metadata-only diagnostics, and import rendered text from its owner.
- Preserve reporting lifetimes: successful store ends store-failure; head movement/empty queue ends stuck/waiting; durable `noticed` survives restart. Replay and deduplicate `queue.startupFindings()` after notifier wiring. Choose waiting states before stuck reasons using AD facts and existing episodes, never pane content.
- Ack reactions use the persona's client and original conversation/timestamp only after final durable receipt. Keep the tracker's 24-hour early-reply memory, 30-day pending/completed-add memory and serialized reply/teardown race handling. Slack failure never blocks FIFO progress; tests reset every map and restore clock replacements.

## Error Handling

- Catch external Slack, file and agent-director failures. Classify AD errors only through `ad-error-class.ts` (`classifyAdError`, `classifyWithInvalidFlagsRecheck`, `isAdErrorInstance`); never add an `instanceof` ladder, class-name comparison or error-string classifier at a site.
- Import error classes through `agent-director-errors.ts`, as named re-exports of the client's own classes. No look-alike classes, namespace/dynamic access or parallel result/parameter fields in `ad-phase1-types.ts`; use the client's types. Otherwise `instanceof` and fields drift from the actual client.
- Keep the closed exceptions in the [error-class contract](architecture.md#agent-director-error-classes-bjg5-srj-104): undeclared names are interpreted only inside the classifier; the existing ambiguous-request, permission-request-not-found, CSCB wrapper and binary-discovery checks keep their specified name handling. Discovery uses the injected resolver and structural fields, with no value import from agent-director. A base error bearing a declared class's name is not that class.
- A launch/recovery refusal is uncounted and non-destructive: no kill, delete, launch/reuse, dead-session verdict or spawn-failure notice/entry. Preserve CONFLICT → UNUSABLE NAME → refusal order through `launchRefusalAt`/`reuseSpawnFailedAt`; use `refusalAt` and `unavailableRetryCauseFor`, including failed sweeps/post-run gets. Read errors never start `tmux-unresponsive`; working-row wait read errors remain transient. Reconnect keys have their own transient mapping and outage reporting.
- Report a site's UNCLASSIFIED result once through `reportUnclassifiedAtSite`, including install disappearance and invalid flags where the verb gives them no meaning. A latched re-check arms/feeds nothing. Reuse-spawn `ErrInvalidFlags` instead enters its hold; never quietly absorb it.
- Every kill uses `checked-kill.ts`, with explicit attempt/teardown context, and its continuation requires `killLetsNextStepRun`. Preserve the row on failure, never retry CONFLICT, and render with `describeKillOutcome`. A successful `kill_sent: false` alone raises nothing; success does not prove a pending launch stopped.
- Retry kills only through `kill-retry.ts`, seeded from the last row reading, with injected clock and keep-going checks. `holdEnded` belongs only to old-life waits. Defer attempt reporting until the standing outcome; report nothing after a stop. Use `survivorPids` for the defined survivor clauses, never a local pid regex, so the worker's pid is not mistaken for a surviving child. Raise the retry's alert decision through the shared alert module.
- Keep CLI teardown's distinct contract in [clean_restart](architecture.md#clean_restart-sr-11-event-12): `checkedKill` plus `runKillRetry`, only `{ instance_id }`, no row delete, latch or Slack post. GONE fails the CLI persona; only UNAVAILABLE retries; CONFIG at a between-try read always ends tries. No server site adopts these CLI-only options. Pass every error through to the checked kill and map with `teardownKillOutcomeOf`.
- Build CLI reports in `cli-teardown.ts`, using the shared alert context/builders. After all personas settle, report in configuration order: terminal, server log, startup-errors entry; print the final line last and only to the terminal. File writes are best effort with `omitStderr`; their failure changes neither exit status nor the other destination. Rejects map through `teardownRejectedOutcomeOf`.
- All CLI waits use `CliDeps.now`/`sleep` and `callWithCliTries`. Keep `teardownBoundMs`/`precheckBoundMs` aligned with call sequences; the post-teardown answer check has its own bound. No direct clock/timer in `createCli`, and every exit uses `CliDeps.exit`, so tests prove bounded operator commands.
- Only start-wide failure exits the process, except the runtime version gate's recorded nonzero shutdown. Per-persona bring-up failures stay isolated. Preserve [startup](architecture.md#server-managed-startup-sr-11-event-1) ordering: validate before ports, PID, Slack or spawn; never fall back from an invalid last-applied record to config. Apply-time template refresh is non-fatal.
- Branch on the startup gate's `refusalKind`, never its diagnostic class/text. `skipPhase1Floor` is allowed only for `stop --stop-bots`; the client's own floor still applies. Server and `clean_restart` keep the CSCB floor, so a human can stop an install the server refuses to run.
- Log errors as one `[slack] context: description` line. Use `describeThrownValue`, `describeAdFailureForLog`, or `describeSlackCallFailure`; additional error text goes through `describeLogMessage`/`redactSlackLogText`. Check direct labels with `isSafeIdentifier`, pass built strings to `recordStartupError`, and keep error text out of reused outcome causes. Never describe a credentials read/parse error: use fixed causes because its message can quote secrets.
- Keep raw-error exceptions closed in `tests/secrecy-audit.test.ts` (`RAW_ERROR_ALLOWED`, with reasons); add safe describers to `SAFE_DESCRIBERS`. Do not pass raw errors, messages or stacks to a log outside those exceptions. Non-critical reactions/updates may use an empty catch marked `/* non-critical */` or `/* ignore */`.

## Session recovery

The detailed [lifecycle contracts](architecture.md#session-lifecycle) define outcome tables and ordering. Reuse their entries rather than adding a parallel recovery path.

- Replace live rows, including `pending`, only through `startLiveRowSequence` and the server's one registry; final launches use its session-manager entry. Never call `runLiveRowSequence` directly in production or kill-then-launch inline. Reuse rows read `ended`/`missing` through `reuseSpawnForPersona`, preserving their history; delete none.
- Start sequences with last-read state, conversation/retired-key flags, alert context and injected clock. The ordinary entry starts at the checked kill; the own-stuck-launch abort enters after its checked kill. Keep grace waits, spacing, bounds and reconciliation in the shared sequence. Unjudged pending rows retry later, uncounted and unalerted.
- `ErrSpawnNotResumable` alone never authorizes replacement. Use `resumeAtSite` and its re-read: `pending` goes to the pending rule; only a known non-pending live state with still-valid dead evidence permits the sequence. Unknown/unreadable state is a lost race. A sequence's final resume cannot start another sequence. Dead evidence covers one life and is void after a gone/ended/missing reading or the specified reconnect verdict.
- Build reuse parameters only in `reuseSpawnForPersona`: ordinary spawn params plus `reuse_finished`, with trust/reply guard and after-launch handling. Distinguish `isReuseSpawnCollided` before interpreting a launch result; never follow a failed reuse with a kill or launch. Count its result only at the designated caller, once. Diagnose lost transcripts before reuse resets the row.
- Read retirement only through `retiredKeyReadingOf`; a recorded key launches by reuse, never plain spawn/resume. Re-read after awaits before acting, carry the attempt-start generation to marking, and mark new life only through the store. Never reconnect into an unmarked old life. Treat `fresh-retired` as success wherever `spawned` is success.
- Use `decidePendingRowCover`, `compareRowToPersona` and the shared pending step; preserve status-site versus ladder ordering. A missing launch start latches first. Unresolvable directories defer rather than imply mismatch. Every covered pending origin arms `armPendingRowWatch`; a status-only site first gets the full row through `readAndStepPendingRow`.
- Run `createPendingRowRule` only through `runPendingRowRuleAtRetry`, once per normal retry, with no independent timer or startup Enter. Before grace G do nothing; after an unjudged sweep do nothing further that round before bound B; after a failed post-sweep get never act on an older read. At B use the rule's current reading. A latch stops all further calls.
- Own-launch identity comes only from `isCscbOwnLaunch`/`recordOwnLaunch`, the call window and authoritative launch start, never labels, transcript, TUI or a local ownership flag. Abort a proved own stuck launch only at step 3, after its relaunching post and fresh latch/outage checks, at most once per episode. Use `abortKillOwnStuckLaunch` and the sequence's step-2 entry. Transient/stopped kills leave the abort unused; retry without a second post.
- Every launch uses `launchCallWithWindow` (directly or through the reply guard). Recognize timeout only through the classifier's class-plus-phrase helpers. After any UNAVAILABLE launch, `afterLaunchUnavailable` makes one shared get and no second launch that attempt. Timeout stays UNAVAILABLE, logs no success/pre-trust and counts no failure. Ownership is the inclusive window only: no tolerance or `started_at`. A timed-out reuse's proved new life uses the same generation-aware mark/hold end as success but still answers `retrying`.
- Handle plain spawn, resume and reuse failures in their shared handlers. LAUNCH FAILURE uses `launchFailureResult`, arming pending-only recovery and carrying `countedClass`; never kill the holder or retry inline. A first non-retired spawn has no reuse flag. Collisions take their collision paths, never a spawn-failure notice or a “dispatcher bug” label.
- Background sequences run detached in their own recovery attempt; never await them from startup, apply or another persona. Stop at latch, teardown and shutdown; competing paths answer `sequence-waiting` without calls. Old-life waits use `ensureOldLifeWait` and the same registry's no-launch form outside attempts; never create another loop or launch the old key.
- Keep old-life holds in the one in-memory `retired-keys.ts` set. End them only on authoritative gone/ended/missing evidence, completed sweep `ids` or new life, never a kill result. Report reads through `noteOldLifeRowRead` unless stopped. Mark kill-failed only from the ordinary non-stopped alert/sequence outcome, never a survivor/success. The [old-life contract](architecture.md#the-old-life-hold-bjg5-srj-809) governs waiter outages, log-only notices and which latch/teardown can stop the wait.

### Shared reads, latches and holds

- Read a persona's own row through `readPersonaOwnRow` or the shared status step; use `decideOwnRowRead`/`actOnOwnRowRead` for listings. Pass the complete client result, not just its state, so launch-start evidence survives. Add latch decisions only to the shared rule. Handle every answer and recheck the latch after awaits before acting. A site exempt from latching documents why; CLI precheck and latch probes keep their specified separate readers. Shared reads own retirement clears, hold observations and episode ends, so sites cannot disagree.
- Read launch starts only through `parseLaunchStart`; age pending rows through `pendingRowAgeOf` with live derived-wait accessors. Render starts with `describeLaunchStartForLog`, never raw fields or a second date formatter.
- CONFLICT and UNUSABLE NAME latch at their shared entries, with the refused operation and last-read state. Missing launch start also latches. Every launch/recovery gate checks the installed latch; no automated call, key or kill acts for a latched persona except the permitted re-check. Not-configured and teardown contexts retain their [routing distinctions](architecture.md#log-only-routing-bjg5-srj-1002).
- Preserve the [re-check](architecture.md#the-re-check-bjg5-srj-505) contract: one timer per persona, its revocable permit only, caps/up/hold gates first, pure one-line outcome probe, no retry of refused kill/send-keys/pause, and no-information answers keep the latch without arming/reporting. A new case relatches and posts once; a same-case refusal does not.
- Clear only through the latch's clear entry; post one recovery reason, then the required bypassing sweep and immediate retry if the clear launched nothing, in the persona's serialized turn. Clear-by-hand awaits `cleared`, not recovery completion. Teardown forgets without a recovery post; shutdown closes; latches never persist across restart.
- Reuse-spawn `ErrInvalidFlags` goes through the classifier re-check and `invalid-flags-hold.ts`. Every automated action checks the hold after the latch (query failure counts as held); held launches run no trust/reply-guard work and count neither success nor failure. Stop the retry timer through the hold reaction, not `conditionEnded`, and leave the unclassified episode alone. End only on version change, teardown or server restart. Preserve its [version-change release rule](architecture.md#the-errinvalidflags-hold-bjg5-srj-207-srj-1008); never clear it through a generic latch or retry outcome.

### Auto-Restart

- Keep failure state per persona in `backoff.ts`, separate from bring-up and UNAVAILABLE timers. Preserve exponential backoff, the five-failure cap and once-per-episode cap notice. Only designated LAUNCH FAILURE/DIRECTORY relaunch results count; refusals, holds, pending/unknown readings and reconnect failures do not. New launch actions need explicit mappings in launch, restart and startup-summary consumers, so a deferral cannot become a success or failure by default.
- A clean-exit fast relaunch requires AD `ended` and the shared gates; preserve the clean-exit cooldown and ordinary delay when the check fails. `session_restart_delay: 0` disables automatic restart. Success of a launch or MCP reconnect resets the failure count and cap-notified latch together. Other resets are only teardown and a clear-by-hand that actually clears a latch; state is in-memory. Preserve [human-triggered delay limits](architecture.md#auto-restart), never resetting on incidental health observations.
- Route post-ack recovery through `handleLostMessage`/`decideLostMessageState`. Preserve priority: not-up, human latch, invalid-flags hold, kill-failed, not-answering, sequence/wait, launch in flight, restart in flight, disabled, cap, starting-now. Not-answering requires its condition, below-cap status and an armed timer; an unclassified episode alone is insufficient. Arm a missing tmux-unavailable retry before deciding, never a competing restart. Accepted items remain queued in every state.
- UNAVAILABLE retry owns its schedule and pending-only mode, never the restart failure counter/backoff. Stop while latched, held, not up or shutting down. Keep one deferred reconnect owner and the [retry outcome table](architecture.md#unavailable-retry-bjg5-srj-303-srj-305).
- `tmux-unresponsive` is a notice condition, not an outage flag: only a tmux-touching UNAVAILABLE inside an attempt starts it. Only a tmux success clears `tmux-unavailable`; only a store-reading success clears `ad-config-malformed`. Use shared outage/condition entries and current readings, preserving [onset/end rules](architecture.md#the-tmux-unresponsive-condition-bjg5-srj-307-srj-310), so a successful metadata read cannot claim tmux recovered.

### Bring-up, health and credentials

- Serve/admit/relay only personas the shared `createPersonaUpPredicate` says are up; `clientFor` alone is insufficient. Keep a not-up persona's instance and row; its status alone authorizes no destructive recovery. `/interject` and cron may durably accept for any configured persona without delivering themselves. On leaving up, drop MCP through `createNotUpSessionDropper` and do no recovery there.
- Check shutdown before the not-up gate, and recheck up/applied status after every await before touching an instance; skips record neither success nor failure.
- Before admission or launch, ask the shared held-directory check. Preserve row comparison's `cwdCheckDeferred` before `cwdMatches`; an unresolvable path is not proof of mismatch. A resolvable different directory still follows normal replacement, so a persona cannot adopt another directory's session.
- Bring-up retries have per-persona 5-second-to-300-second exponential schedules, no cap and no restart-counter access. Free startup pool slots for retries and parked working-row waits. Reuse confirmed credentials, never reread edits silently; launch once through `spawnForPersona` on becoming up. A running persona losing its directory stays on ordinary restart recovery. Log onset/clear only, without Slack/startup-errors entries, because a broken persona has no validated posting identity.
- Health checks skip restart-in-flight and capped personas before reads. Latch, hold, work-in-flight and outage are no-attempt guards, not skips: reads must still be able to clear conditions. Add guards through `NoAttemptReason`, preserve their order and missing-timer rule, and treat unknown liveness as no action/episode clear. Dead schedules restart; live plus connected is healthy. Readiness remains agent-director's, never elapsed quiet time or screen content. See [Health-Check Poller](architecture.md#health-check-poller).
- Credentials reconnect uses the shared attempt code, with every Slack `start()` bounded at 10 seconds. Reach `hello` before atomically swapping token/identity/client/socket, then close the old connection. Failure keeps the old connection and pending change; Slack-unreachable retries independently. Serialize the first attempt only, keeping the persona up and siblings unblocked.
- Clear per-Slack-identity caches in `beforeSwap`, keep held and live credentials separate, and end every cancelled reconnect episode. Credentials-broken recovers only through confirmed change, judged when apply runs. Wrap every long-lived client with `watchWebClientAuth`; auth refusal marks broken immediately, while only detached network close waits on the serializer.

## The Start Sweep

- `reconcileOrphans` lists once with service label only, processes own-row rules and records absent persona keys/old-life holds before the first kill. Use the shared stores, act rules and per-row records; no second list/state filter or independent counters.
- A pre-persona row is killed when live through the checked kill, and its row is kept. Kill only listed-live stray/pre-persona rows, never ended/missing or latched rows, using checked bounded retry and one pass budget. Record each unsuccessful kill; sweep notices are log/startup-errors entries, not Slack posts, except the specified applied-persona ENVIRONMENT/CONFIG onsets.
- All `findMissing` calls go through `sharedFindMissingSweep`, retaining its memo/bypass rules, joined-caller refusals and post-run gets. Reconcile after kills; an unjudged pending row means retry later. Leave post-run own-row reads to the core and check the latch afterward.
- Check live shutdown state before calls and before acting on settled answers. After stop, make no call, latch, write, clear or outage raise; count unreached rows kept. Every sweep that listed rows ends with its one summary, including stopped sweeps. Preserve the [startup sweep contract](architecture.md#server-managed-startup-sr-11-event-1), so retries cannot mutate state during shutdown.

## Configuration

- Read running configuration from the reload controller; only operator confirmation applies edits. The CLI uses `readAppliedPersonaConfig` (record first) and never writes reload/retired-key files or touches/imports the stored-choice store directly. The credentials command's current-config lookup and file-send guard's current-file protection are their specified exceptions; clear-latch uses the live `server.port`.
- Parse bytes once through `parsePersonaConfigBytes`; report JSON position without parser text/file content. Only `referencedCredentialsPaths` tolerantly extracts paths, discarding parse errors, so protection still sees invalid edits.
- Config/record/credentials readers are stat-first, non-blocking, regular-file-only and capped at 64 KiB both before and during read. Use `readPersonaConfigBytes`/`readCredentialsFile`. `uncapped` is allowed only for file-send credential protection and server-start retired-key/stored-choice loads; recorded/applied/digested/compared bytes stay capped.
- Resolve server paths with `resolveServerStateDir`/`resolveServerConfigPath`, CLI/postinstall paths with `resolveCliStateDir`/`resolveCliConfigPath`, and cron/XDG defaults with their shared resolvers. Never hand-join defaults or read environment outside the injectable resolver. Run `migrateStateDirAtStart` first in `main()`, never CLI/postinstall; preserve no-overwrite, live-server stop, atomic old-name link swap, log repoint and failure-stop rules in [startup](architecture.md#server-managed-startup-sr-11-event-1).
- Only the server's single `retired-keys.ts` store reads/writes retired keys; unreadable/invalid data stops startup, never becomes an empty record. Only its single `channel-delivery.ts` store reads/writes stored choices; unreadable data stays on disk and disables choices/writes for the run, falling back to mentions. Load it immediately after config resolution, before the next await, in both modes and dry run; access it at call time. ## Security

- Validate external input at boundaries. Generic external errors expose no stack, sensitive detail or internal paths; safe diagnostic detail goes to stderr.
- Local-only routes use `isLocalAddress(server.requestIP(req))`, accepting the defined loopback forms, never forwarding headers or a second check. Handlers are import-safe injected modules; `server.ts` only wires them. CLI-imported handlers load no server-only modules.
- Clear-latch is operator-only: one injected `clearByHand` call, no argument echo, generic failure response. CLI dials only `127.0.0.1` through `node:http` with `agent: false`, never proxy-aware fetch, using a validated port record matching `readServerPid`. It removes no record and names unexpected responses by status only. Its injected wait timeout means “did not confirm”, not “did not answer”, because the clear may still run.
- Keep reload unadvertised in CLI flags, tools, endpoints and MCP instructions. Its confirmation is the operator-directed pending-to-apply rename; only operator docs/skills describe it. Never expose clear-latch in any spelling to tools, instructions, reply-guard reminders or Slack notices. Its descriptions belong only in CLI usage/reference and debugging skill. Check tool refusal/result texts by hand as well as audited definitions; deliberate opacity is not a same-user security boundary.
- Slack tokens come only from persona credentials files, never config/source/environment; tests use fakes. Read only with `readCredentialsFile`; never copy/persist/log contents, and keep tokens only in the required connection state. Do not check/warn/change operator file permissions in the server. The operator-run packaged credentials script alone creates its file with mode 0600.
- Skills never ask for/accept/show token values or dump credentials files. The credentials command runs the packaged bash script on the operator's terminal with no-echo prompts; tokens reach curl only on stdin, never arguments/environment/output. Keep bash/zsh compatibility, the wizard's short persona-only command and the script in package `files`. Shape checks show keys/prefixes only.
- Compare credentials by in-memory digest/missing marker, never persisted/logged. Discard tick bytes after the pass; shared-file broken personas hash their own path without parsing tokens. Keep digests out of plans/previews; the fingerprint lives only in pending state. No credentials content enters any server output, exception, Slack post or tool result.
- Build every persona Slack client through the manager's injected factory and option builders, with `attachOriginalToWebAPIRequestError: false` and its safe logger. Socket logs admit only fixed health lines (numbers at most), never runtime details/ticket URLs; Web API logs redact token/URL-like text. Log failures through safe describers.
- `CSCB_SLACK_API_URL` stays test-only: literal HTTP loopback, no userinfo/query/fragment, no hostname; read only in `main()` through its resolver. Reject without echo and log only origin, never path. Do not document it for operators, since clients send tokens to the selected listener.
- Tool errors name persona/target and safe Slack reason only. Stored-choice output may show validated arguments, file path, keys, IDs, counts/positions and codes, never stored values or raw messages. Any new untrusted echoed field needs its own validation. Redact permission-trail `raw_error_message` and every other raw log/file text.
- Do not add a persona-name format rule or redact names, configured paths or `ack_reaction`; message content remains archived/debug-logged as specified. Redaction is for Slack library output/thrown values and credentials, not a new content policy.
- Preserve self-exclusion as the only sender filter: no sender allowlist, approval, arbitration or cross-persona throttle. Intake uses applied config, stored choices and event envelope only. Fungible mode rejects externally shared channels and keeps other personas' destination channels at mentions; DMs depend on `dm.enabled`, group DMs never deliver. See the [security model](architecture.md#security-model).
- Every MCP call resolves its persona at call time; Slack-target tools also resolve its client and pass `checkPersonaTarget` before any Slack call, even dry run. Refusals are tool errors, not protocol throws. Declarative targets are configured channels; fungible channel membership is Slack's decision. `set_channel_delivery` has no Slack target/client/call/check and stores in dry run too.
- With DMs off, refuse channel/user DM targets before any Slack call. With DMs on, only reply accepts user IDs, opens through the persona's client and writes to the returned conversation ID; read/edit/reaction never opens a DM. Prompt updates use the recorded original conversation/client, never a fresh destination or DM-enabled check.

## Async Patterns

- Use async/await; raw Promises are for explicitly held connections. SSE resolves on request abort and writes through the response; clean up every held connection on abort. Use a settled flag where races could resolve twice.
- Bound potentially non-settling Slack operations on the injected clock and catch/disconnect late results. Keep locks, queues, promise chains and timers per persona so one cannot block another.
- Multi-item ticks catch per item, log a repeating failure once and continue. Intervals call `tick().catch(...)` with a last-resort once-until-success logger, never unhandled `void tick()`.
- Startup AD/file-changing passes and queued launches check a live shutdown query before acting and after awaits; throws mean stop. Never capture a stale flag. No queued launch starts after shutdown; record its explicit not-launched outcome without failure counts.

## Definition of Done

Apiary statuses are `draft`, `defined`, `active`, `done`, plus `invalid` for Bugs. They describe tickets, not agent-director rows. Only the assigned skill's owner changes its statuses. The orchestrator (Managing Intelligence) sets PRDs/SRDs `defined` on approval, then a `draft` Idea `defined` once both are approved, and sets Ideas/Bugs `done` on acceptance after testing; engineers and reviewers do not accept their own work.

Before handing back implementation:

Acceptance and merge are separate gates: Ideas/Bugs become `done` on acceptance, then `teardown-worktree` merges them, then `release` follows the Project's release guide. Record the artifact path or reason and where superseding work lives; do not silently strand accepted commits.
